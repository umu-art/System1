# Flyway при раскатке System1

Дизайн согласован: сборка образов → одноразовый Kubernetes Job Flyway → ArgoCD sync → перезапуск обновлённых Deployment. Job использует SQL из того же SHA и выполняется один раз на раскатку, а не на сервис. Stage и prod начинают с чистой БД. История общая: `public.flyway_schema_history`. Автоматический baseline запрещён; ошибка или таймаут блокирует шаги раскатки.

Отдельный шаг в GitHub Actions выбран вместо PreSync отдельного приложения ArgoCD: независимые приложения не ждут его hook. Секреты приходят из Vault через ExternalSecret в namespace окружения; постоянного Pod и запуска миграций из сервиса нет. Реальные окружения в ходе разработки не меняются.
