# api

Контракты между сервисами System1 в OpenAPI 3.1 и генерация кода из них. Бизнес-логики здесь нет.

```
api/
├── build/     сгенерированный код, в git не попадает
├── config/    конфиги генерации и правила линтера
├── src/       контракты
└── build.py   сборка
```

## Сборка

```bash
python api/build.py
python api/build.py --langs go
python api/build.py --force
```

Нужны Python 3 с `pyyaml` и `build`, Java 17+, Redocly CLI, `wget`, Node для TS-клиента. При первом запуске скачивается OpenAPI Generator 7.27.0.

Проверка контракта линтером:

```bash
cd api && redocly lint --config config/lint.yaml src/s1-dialogs.yaml
```

## Как устроено

- Один файл `src/<сервис>.yaml` — контракт одного сервиса. Пути начинаются с `/api/<сервис без префикса s1->/`.
- Один файл `config/<язык>-<сервис>-config.yaml` — одна цель генерации. `sources` — какие файлы из `src` в неё входят, `target` — каталог в `build`.
- Цели по языкам:

  | Префикс конфига | Генератор | Что получается | Кто использует |
  |---|---|---|---|
  | `go-` | `go-echo-server` | интерфейс и роуты Echo | Go-сервис через `replace` в `go.mod` группы |
  | `python-` | `python-fastapi` | `router` и `Base…Api`, wheel в `dist/`, ставится в текущий Python | Python-сервис наследует `Base…Api` |
  | `ts-` | `typescript-fetch` | клиент `s1-ui-api` из всех контрактов | UI через `file:` зависимость |

- Имя цели в `build` начинается с языка (`python-…`, `ts-…`): по нему `build.py` решает, как ставить результат. Go-цели называются `s1-…-api` и ничем не ставятся.
- `src/common.yaml` и `src/scenario.yaml` путей не содержат. Это схемы, на которые контракты ссылаются через `$ref`.

## Что нужно знать

- Файл без путей попадает в сборку только через `$ref` из контракта сервиса. Сам по себе он не генерируется.
- `oneOf` с дискриминатором в Go превращается в одну структуру со всеми полями вариантов. Поэтому шаг сценария описан конвертом: `type` и свободные `params`.
- `src/scenario.yaml` — заготовка. Формат сценария определяет команда.
- Python-пакет в `setup.cfg` тянет `fastapi[all]`. В образ он ставится с `--no-deps`, зависимости берутся из `requirements.txt` сервиса.
